# 出海试衣间 · The Local Edit

> 给好产品换一种表达，让每一句承诺有据可依。

2026 软件工程实践周作品，主题：**湾区出海创新**。

- 在线体验：https://chuhai-fitting-room-2026.heroicmars2.chatgpt.site/
- 演示视频：https://chuhai-fitting-room-2026.heroicmars2.chatgpt.site/demo.html
- 公开源码：https://github.com/witness-echo/chuhai-fitting-room

## 项目解决的问题

小商家准备出海商品文案时，需要保留材质、规格等事实，调整表达，同时防止出现未证实的功效、认证或配送承诺。本项目把事实档案、双语表达、规则复核和商品卡片导出放在同一张可视化工作台上。

## 已实现

1. 三个策划案例：竹编夜灯、山水陶瓷茶杯、城市漫游帆布袋。
2. 英文 / 日文切换，温暖自然 / 简洁实用 / 礼物叙事三种标题风格。
3. 原文与中文释义对照、可展开的改写依据。
4. “事实锁”：常见功效、认证、配送、排名、工艺身份与语境表达规则，以及新增数字检查。
5. 任意候选文案检查与可一键载入的反例。
6. 根据缺失交易与使用信息生成规则追问。
7. 本地图片载入，导出 1080×1350 PNG 商品卡片、Markdown 文案与报告。
8. 自定义事实修改后降级为明确标注的规则草稿，避免使用与新事实不匹配的旧示例。
9. 本地草稿恢复、深浅色切换、移动布局、键盘操作与减少动态效果支持。

## 诚实的能力边界

当前交付是**无需模型密钥的示例与规则版**，没有调用大语言模型。预置外语文案是人工策划内容，风格切换改变标题表达。用户修改商品事实后，系统仅整理原始事实，未知中文保留原文，并标注“规则草稿 · 待翻译”。

事实锁是可解释的启发式规则，不是完整语义核验、认证核验或法律合规审查；只能识别已覆盖的词形、部分常见否定表达和数字差异，不理解所有语境，不进行单位换算，可能误报或漏报。“未命中当前规则”不等于内容正确。事实输入由用户负责确认。模拟顾客追问不是调研结果。商品图为原创 SVG 示意插画。

## 本地运行

安装 Node.js 22 或更高版本，解压项目后运行：

```sh
npm start
```

访问 http://localhost:4173 。项目没有运行时第三方依赖，无需 `npm install`。也可运行 `node server.mjs`。不要直接双击 index.html：浏览器的 file 协议可能阻止 ES Module 加载。

## 测试

```sh
npm test
```

测试覆盖全部 18 种预置语言与风格组合的规格保留、自定义事实降级、四类不实承诺、常见否定处理、已有配送依据、宣传语与事实分离、事实缺口追问。测试不表示翻译质量或真实业务效果已得到第三方验证。

## 架构

```text
商品档案 → core.generate() → 策划示例 / 规则草稿
                       ↓
原始文案 → core.audit() → 风险与解释
候选文案 → core.audit() → 新增承诺和数字差异
商品档案 → core.questions() → 缺失信息追问
                       ↓
          浏览器预览 → PNG / Markdown
```

| 文件 | 作用 |
| --- | --- |
| dist/index.html | 语义化工作台与交互入口 |
| dist/style.css | 集中设计变量、响应式布局、主题与焦点样式 |
| dist/core.js | 示例数据、生成规则、风险匹配与追问，独立可测试 |
| dist/app.js | 表单、状态、标签页、文件读写与 Canvas 导出 |
| dist/assets/ | 原创产品示意 SVG |
| server.mjs | 仅监听本机的静态开发服务器 |
| tests/core.test.mjs | Node 内置测试 |

## 隐私与部署

网站无注册、无数据库、无广告追踪。商品图通过浏览器 FileReader 处理，不发送给服务端；草稿存于本机 localStorage。网站访问仍会产生托管平台的常规访问日志。正式发布前不要填写商业机密或未经授权的数据。

`dist/` 可直接部署到任意静态网站服务。本仓库不包含大型演示视频二进制；`demo.html` 使用公开托管的视频地址。部署到其他地址时仍可播放原视频，或将视频放入新站点并修改地址。
